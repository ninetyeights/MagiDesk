# MagiDesk 首版发布与使用

当前版本：0.1.0-beta.1。首版提供安装版与便携版，均为测试版，优先支持 Windows 11 x64；Windows 10、ARM64、远程桌面和混合 DPI 仍需对应环境实机验收，不承诺已全面验证。

## 下载与首次启动

安装版：运行文件名含 `Setup` 的 EXE，默认安装到 `%LOCALAPPDATA%\Programs\MagiDesk`，无需管理员权限。开始菜单入口自动创建，桌面快捷方式可选；不默认设置开机自启。安装完成后可勾选启动。若已运行，请先从托盘退出；安装器不会强制终止应用。

后续升级直接运行新版安装包，沿用安装目录。可在 Windows“已安装的应用”卸载；卸载保留 `%APPDATA%\MagiDesk` 配置、真实桌面文件和映射目录，只清理属于当前安装路径的开机自启项。安装包当前未做代码签名；安装、升级及卸载的实际流程仍需用户验收。


使用自包含 ZIP 包，无需另装 .NET。完整解压到固定目录，再运行 MagiDesk.exe，不要在 ZIP 内直接运行。首次启动仅开启窗口拖动，其他工具在相应页面手动开启。Alt + 左键拖动移动窗口，Alt + 右键拖动调整大小。

普通使用不需要管理员权限；操作提权应用可能受到 Windows 权限限制。不要为排障关闭系统安全功能。若与其他窗口管理工具的快捷键冲突，请修改快捷键或关闭其中一方对应功能。

默认关闭主窗口会隐藏到托盘，双击托盘图标重新打开，从托盘菜单退出。设置中关闭托盘图标后，关闭主窗口会退出应用。

## 升级、配置与恢复

1. 从托盘退出旧版，确认不再运行。
2. 备份 `%APPDATA%\MagiDesk` 整个目录。配置不保存在解压目录中，复制新版不会重置配置。
3. 将新版完整解压到新目录或退出后的原目录，启动 MagiDesk.exe。移动目录后检查开机自启设置。

配置使用原子写入，保留 `config.json.bak` 和 `backups/config-YYYYMMDD.json`（最近七个备份日）。启动时依次尝试主配置、上次备份、由新到旧的每日备份；恢复时显示提示，不可解析的主文件保留为 `.broken-*`。全部无法读取时使用默认设置并提示，不代表桌面文件被删除。

保存失败会提示，设置页可“重试保存”。不要在保存失败后直接退出并假定新设置已经持久化。手动恢复前先退出应用并备份整个配置目录，将所需快照复制为 `config.json` 后重启。降级前也应备份，不保证旧版能理解新版字段。

桌面盒子的统一桌面模式改变系统图标的显示，不是把真实桌面文件整体搬走。正常退出及恢复辅助进程负责恢复系统桌面；若出现异常，先正常退出，再检查资源管理器及桌面“显示桌面图标”状态。

## 诊断与已知限制

常规错误日志：`%TEMP%\magidesk.log`，单文件约 2 MiB，保留一个轮转文件。反馈问题请附版本、显示器缩放、复现步骤及相关日志，并检查日志中是否有个人路径等信息。

详细性能诊断默认关闭。确需排障时，在 PowerShell 中设置 `$env:MAGIDESK_DIAGNOSTICS='1'` 后从同一终端启动应用。结束后退出应用，并执行 `Remove-Item Env:MAGIDESK_DIAGNOSTICS`；已写入日志不会自动清空。详细模式会启用前 90 秒的启动／内存采样，并可能包含更多窗口信息。

- 快速网格跨 DPI 恢复资源管理器时，可能存在短暂空白／过渡等待，仍待进一步优化。
- 分区预览当前保留 WPF 预热方案；原生渲染替换尚未实施。
- 无窗口测试不能覆盖真实窗口层级、Shell 扩展、屏幕热插拔及远程桌面恢复。
- 支持自动检查及确认后安装更新；未发布公开 Release 前，客户端会提示更新源不可用。

## 开发者发布流程

在仓库根目录执行 `powershell -ExecutionPolicy Bypass -File scripts/Publish-Release.ps1` 生成便携版；添加 `-Installer` 同时生成安装 EXE。安装包构建需要 Inno Setup 6.3+，可用 `-InnoCompiler "完整路径\ISCC.exe"` 指定编译器。脚本不会自动安装构建工具。脚本读取项目版本，临时目录构建 Release、运行无窗口测试、发布自包含包，输出到 `publish`，ZIP 与安装 EXE 各附 SHA256 和包内 `build-info.json`。不会启动应用，也不会修改用户配置。默认 win-x64；ARM64 包需要在对应设备另行验收。

发布前核对：全新配置与旧配置升级、桌面异常恢复、真实文件操作取消／冲突、Dock 工作区释放、混合 DPI、远程桌面和脱离调试器的内存基线。测试结果、版本和已知问题应随发布记录一起保留。源码授权方案和第三方依赖声明在公开分发前单独确认，本文不授予开源许可。

## 自动更新与版本发布

“关于 MagiDesk”中可以手动检查更新、查看更新说明、下载／取消下载，再点击“退出并安装”。自动检查默认关闭；开启后约 30 秒首次检查，此后每 12 小时检查一次，同一运行会话不会重复提醒同一版本。点击托盘更新提醒可进入关于页。检查失败不会中断其他功能。

更新源固定为 `https://api.github.com/repos/ninetyeights/MagiDesk/releases`，不携带账号或访问令牌。正式版只接收正式版；当前为测试版时也接收更高的测试版。版本按语义版本比较，匹配当前进程架构，不安装同版本或更旧版本。

发布者需执行以下步骤（构建脚本不会代为公开发布）：

1. 修改项目中的 `Version`，更新 `AssemblyVersion`／`FileVersion` 和 CHANGELOG。
2. 按 `UPDATE-SIGNING.md` 初始化并备份正式私钥，重新构建嵌入公钥；执行 `scripts/Publish-Release.ps1 -Installer`，取得安装 EXE，再通过独立签名工具生成清单和签名。
3. 在上述公开仓库创建 Release，标签必须为 `v版本号`（如 `v0.1.0-beta.2`），测试版勾选 prerelease。
4. 将安装 EXE、`update-manifest.json` 和二进制 `update-manifest.sig` 一起上传同一个 Release，保留文件名。x64／ARM64 用同一份签名清单描述；只有 ZIP 或 `.sha256` 不会提供应用内安装更新。
5. 在较旧版本中手动检查并实机验证升级、退出恢复和新版本启动。

下载写入 `%LOCALAPPDATA%\MagiDesk\Updates`，进度可见，失败／取消会清理本次不完整文件；下载大小及 SHA256 必须匹配。客户端和退出后的独立助手均验证清单签名，再验证安装包大小及 SHA256；未知密钥、缺少签名或验证失败会停止。该签名不等于 Windows Authenticode 代码签名。便携版通过此入口会转为安装版，原解压目录不会自动删除。

本轮验证公开 API 返回 404，在线发布端尚未就绪或不可公开访问。版本筛选、校验、下载失败等已使用模拟响应验证；完整在线升级与真实安装仍待发布后验收。

## SEC-08：发布检查

发布脚本现在先运行 `scripts/Test-Security.ps1`：强制锁定依赖还原并检查全部依赖漏洞，然后使用固定版本和摘要的 Gitleaks 扫描本地 Git 历史和当前可提交文件。任一步失败都停止打包。需要访问 NuGet 官方源及 GitHub 工具下载源；不把网络失败当作检查通过。升级依赖须主动更新三个锁文件，操作见 `DEPENDENCY-SECURITY.md`。

CI 配置已加入源码，推送后再确认实际运行和必需检查设置；本地配置完成不代表远端保护已开启。

Actions + tag 的完整草稿、签名和发布步骤见 `UPDATE-SIGNING.md`。发行包同时附带依赖的许可证及第三方声明；公开源码本身不自动授予额外开源许可。
